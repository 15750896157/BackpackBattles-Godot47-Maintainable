四、存档问题的原因、修复与保护
规划第19章要求未结束的远征能继续，并规定战斗中退出由相同快照和随机种子重播；战败才结束本局。
此前主菜单刷新中播放的“隐藏认输”动画，在原 Main.tscn 中同时隐藏了 Continue 节点。
因此即使磁盘存档有效且继续按钮未禁用，下一帧继续入口仍不可见。之前只调用继续方法的测试遗漏了可见入口。
这属于实现及验收遗漏，不是策划要求，也不是“保存并”三个字代替真正保存。
用户随后点击标准新开局入口，原实现又缺少独立旧局归档保护，可能替换尚未结束的 run 存档。

本轮修复：
1. 停止旧隐藏动画；认输与继续分别控制。继续横幅使用原素材，移开两个新开局旗帜，防止互相遮挡。
2. 有效未完结单局显示“继续游戏”；标准/教学出发进入新开局设置；设置页另提供“继续上次远征”。
3. 进行中开新局必须明确确认替换；确认后先将旧单局完整封装复制至 pve/archives/<旧局ID_时间>/run.save。
4. 归档读回和 SHA 校验成功才继续创建新局；备份失败阻止覆盖并保留旧进度。
5. 主存档损坏仍可读取滚动备份并提示恢复；JSON 损坏的预期恢复路径改用可检查的解析错误返回。
6. 单局、档案、设置继续分开保存，现有 schema 2 与内容版本保持兼容。

实际玩家目录：%APPDATA%\BackpackBattles_Local47_PvE\pve。
本轮七份现有玩家文件的测试前后 SHA 全部一致；所有自动验收使用隔离目录。
检查时当前主单局与滚动备份都只保留早期商店状态，未找到用户描述的更晚背包记录。
已经被覆盖且没有剩余主档/滚动备份/独立归档的数据无法凭空恢复；本报告不声称找回那部分旧物品。
run 是当前单局，profile 是累计解锁/图鉴/统计，settings 是设置。独立归档保留单局而非回滚整个累计档案。
手动恢复归档前先关闭游戏并另存当前 pve 文件夹，再将选中归档的 run.save 复制回 pve/run.save，启动后点继续。
