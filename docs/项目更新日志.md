## 【2026-11-25 18:25】仓库格子自由放置：入库可指定槽位、仓库内可交换

**计划**
处理《背包乱斗美术产出表 (3)》"程序美术问题"表第 29 行：仓库的物品只能按顺序放，买的第一个东西只能放在第一格，不能放到第二、三格。

**实际做了**
- 排查结论：数据层 `PlacementService.store()` 只会 append 到仓库列表末尾（槽位=列表下标），UI 层 `NativeBuildBridge.drop_item()` 只要落进仓库范围就入库，完全不看落点在哪个格子；仓库内也没有任何重排入口。
- 数据层（PlacementService.gd）：仓库条目新增可选 `slot` 字段；`store()/remove()` 支持指定槽位（缺省 -1 保持原顺序追加，兼容旧存档与既有测试）；`validate()` 校验槽位范围与占用（新错误码 storage_slot / storage_slot_occupied）；`swap()` 仓库↔仓库交换槽位值，仓库↔背包交换时背包侧物品带入仓库槽位、入库侧物品清除 slot。
- 流程层（GameFlow.gd）：`edit("store")` 透传 `options.slot`；奖励入库等无落点路径保持顺序追加。
- UI 层（NativeBuildBridge.gd）：投放时按物品中心映射 `pve_slot_rect` 计算目标格（_storage_drop_slot）；目标格被其它仓库物品占用 → 走既有 swap 交换（商店货买入后自动交换，含仓库↔背包与仓库↔仓库两种），空格 → 直接入该格（_storage_occupant）；渲染与 `_restore_native` 按条目 slot 摆位。
- 表现层（Presentation.gd）：桌布仓库刷新循环按条目 slot 摆位，不再按列表下标。
- 验收：`verify_native.ps1` 全量 34 场景通过（报告 `verification/local_check_20261125_175658_553`），数据层"148 件物品、149 条效果"一致，退出码 0 无 SCRIPT ERROR。改动仅 4 个 gd 文件（PlacementService / GameFlow / NativeBuildBridge / Presentation）。
- 修正（用户实测仍不行后定位）：初版落点判定用"物品视觉中心"，与原生 `isHovered` 的"物品原点"相差一个抓取偏移（约 40px），判定偏一格或落空回退成顺序追加。改为**鼠标优先**的多参考点判定（鼠标 → 物品原点 → 视觉中心，命中任一即生效），悬停判定放宽到整个画布方格区域（含方格间空隙）。定向探针（临时场景，已删除）15 项断言全过：容量 2 时第一件商品丢第 2 格入库 slot=1、扩容 4 后丢第 3/4 格 slot=2/3、丢到占用格自动交换。复跑全量 34 场景验收通过（报告 `verification/local_check_20261125_183925_686`）。
- 备注：本机沙箱会话曾同时注入 HTTPS_PROXY 与 https_proxy 重复环境变量导致 Start-Process 启动引擎失败，进程内清理后重跑通过，与游戏代码无关。
